# GuildFrontierSim

冒険者ギルドの経営と RPG 戦闘を組み合わせた、Unity 製シミュレーションゲームです。

プレイヤーはギルド所属の冒険者として活動し、状況に応じてギルドリーダーとして人員配置、防衛、遠征、資金管理などを行います。プレイヤーが経営を担当できない場合も、CPU がギルドの運営を継続します。

> Phase 1「経営自動シミュレーション」のプレイ可能なプロトタイプが完成しています。

## ゲームの特徴

- 冒険者ギルドの資金・人員管理
- メンバーを割り当てる防衛戦と遠征
- CPU による自動メンバー選択とギルド経営
- ステータスから結果を計算する自動戦闘
- 負傷、入院、休業、虜囚、救出
- 給料と忠誠度、メンバー離脱
- リーダー不在時の代理選出とリーダー交代
- 将来追加するコマンド RPG 戦闘
- キャラクターメイク、NPC 会話、好感度、スカウト
- WPF／ComfyUIによるキャラクターグラフィック制作

## 現在の開発状況

Phase 1 の実装と完成確認が完了しています。Unityで`MainScene`を再生し、ボタンからターンを進めると、CPUによる防衛・遠征・給料・忠誠度・回復・リーダー処理を確認できます。

現在実行できるゲームサイクルは次のとおりです。

```text
ギルド状態確認
    ↓
防衛・遠征メンバーをCPUが選択
    ↓
自動戦闘と遠征進行
    ↓
報酬・負傷・虜囚などを反映
    ↓
給料と忠誠度を処理
    ↓
次のターン
```

### Phase 1の最低目標

- 数人のギルドメンバーと初期資金で開始できる
- ボタンからターンを連続して進められる
- CPU が防衛・遠征メンバーを選択する
- 自動戦闘によって勝敗が決まる
- 資金、アイテム、給料、忠誠度が変化する
- 負傷、入院、虜囚、救出、帰還が発生する
- リーダーが活動不能になった場合に代理または後任が決まる
- 状態変化を最小 UI または `Debug.Log` で確認できる

上記の最低目標はすべて実装済みです。確認内容は[Phase 1完成確認レポート](Docs/Phase1CompletionReport.md)を参照してください。

## セットアップ

1. リポジトリをGit LFS対応のGitクライアントで取得します。

   ```shell
   git lfs install
   git clone <repository-url>
   ```

2. Unity Hubでリポジトリのルートフォルダを追加します。
3. Unity `2021.3.45f2` でプロジェクトを開きます。
4. Package Managerによるパッケージ復元と、初回インポートの完了を待ちます。
5. `Assets/Scenes/MainScene.unity` を開きます。
6. Unityの再生ボタンを押します。
7. 画面の「次のターン」を押してシミュレーションを進めます。「最初から」で初期状態へ戻せます。

### テストと開発ビルド

- EditModeテスト: 136件
- PlayModeテスト: 1件（実シーンのターン進行とリセット）
- Windows 64-bit Development Build: 作成・起動確認済み

Unity Editorメニューの`Guild Frontier Sim > Build Windows Development Player`から、`Builds/Windows`へ開発ビルドを生成できます。`Builds`フォルダはGit管理対象外です。

`Library`、`Logs`、`UserSettings`などはGit管理されません。これらを手動で共有する必要はありません。

## キャラクターグラフィック制作

キャラクター画像はUnity内で生成しません。将来的に、独立したWPFツールからComfyUIへ接続して制作します。

```text
WPFツール
  ├─ 外見・プロンプト指定
  ├─ ComfyUIへの生成要求
  ├─ 候補画像の比較と採用
  └─ 画像とメタデータを書き出し
                    ↓
Unity
  ├─ 採用済み画像をインポート
  ├─ visualIdでキャラクターと関連付け
  └─ 画像欠損時は既定画像を表示
```

UnityはComfyUIへ直接接続しません。そのため、ComfyUIやWPFツールがなくてもゲーム本体を開発・実行できる設計にします。

## ロードマップ

### Phase 1：経営自動シミュレーション

完了。ターン進行、CPU経営、自動戦闘、防衛、遠征、給料、忠誠度、負傷、虜囚、リーダー交代、最小UIを実装済みです。

### Phase 2：手動経営

防衛・遠征メンバー、遠征先、遠征継続、代理ギルド長などをプレイヤーが選択できるようにします。

### Phase 3：プレイヤー冒険者モード

CPUが経営するギルドで、プレイヤーが一般冒険者として防衛、遠征、クエストへ参加できるようにします。

### Phase 4：コマンドRPG戦闘

プレイヤーが参加する戦闘を操作可能にします。戦闘結果は共通の `BattleResult` を通じて経営側へ反映します。

### Phase 5：キャラクター・イベント拡張

キャラクターメイク、NPC、会話、好感度、スカウト、イベント戦闘、WPFツールで制作した画像の本格統合を追加します。

## 開発方針

- 一度にすべてを実装せず、フェーズ単位で動作を完成させる
- MonoBehaviourへゲームロジックを集中させない
- UI、経営、戦闘、CPU判断の責務を分離する
- ScriptableObjectは主に設定・マスターデータへ使用する
- プレイ中の状態とマスターデータを分離する
- ゲームバランス値をコードへ大量にハードコードしない
- Unity UIはEditor上で構築し、GameObjectの大量コード生成を避ける
- 外部ツールや画像がなくてもゲームロジックを動作させる
- 自動テスト可能な純粋C#ロジックを優先する
